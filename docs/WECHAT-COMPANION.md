# 微信 AI 陪听 · 第一阶段

微信中发送已开启的公开房间链接并 @机器人，她会以该微信会话绑定的 AiChat 角色名称加入房间。网站沿用成员与队列界面，不增加聊天；本阶段不把歌曲、歌词或房间消息传给模型。

## 启用

1. 先发布音乐服务端，再更新 AiChat。音乐站管理后台的「系统设置 → AI 服务与陪听」中，开启「微信 AI 陪听」，生成或填写至少 32 字符的连接密钥并保存。复制新生成的密钥到 AiChat；已保存的密钥不会完整回显。不需要启用原有聊天室 AI 或配置模型。
2. 在 AiChat 工作台打开「AI 陪听」，填写音乐站根地址和相同的连接密钥。选中允许邀请的微信会话，开启陪听并保存。该会话也需要在用户列表中启用监听；群聊需要真正 @机器人，私聊发送链接即可。
3. 在网站创建或加入公开房间，点击「邀请朋友」复制链接，在选定微信会话发送 `@她 https://你的站点/room/房间号`。需要至少一位真实听友在线。密码房、无密码上锁房间暂不支持，不能通过连接密钥绕过。
4. 网站「正在一起听」显示角色名及「AI 陪听」。微信确认入房；首次选歌可能需要等待歌源响应。工作台的「AI 陪听」显示活动房间和续歌失败状态。
5. 结束时在微信发送 `@她 结束陪听`，私聊不需要 @。切换房间先结束当前陪听。停止微信 bot 也会结束陪听；真人全部离开后自动退出。

## 队列行为

- bot 待播最多一首，固定在最后。真人点歌排在她前面；随机、轮流和收藏随机模式也优先消费真人待播。单曲循环仍遵循用户选定的循环模式。
- bot 歌曲开始播放后再补下一首；列表循环不会回收 bot 歌曲制造重复。点赞、拖动排序不能把自动续歌提前。
- 选曲复用房间指定歌单、收藏随机或私人漫游；普通漫游关闭时，陪听使用该房间音源的默认推荐。遵守禁播、排除当前和待播重复，尽量避开最近十首。少量歌曲的歌单允许在后续轮次重播。
- 每次最多尝试三首候选；没有可用歌曲或上游失败时，至少间隔 30 秒再尝试。通过现有服务端取链探测过滤明确不可播的歌曲；外部上游异常仍可能导致播放失败，不保证所有候选实际可播放。
- 遵守队列长度上限；队列已满时，腾出位置后再补歌。清空或移除 bot 待播会重新补歌，停止自动补歌请结束陪听。
- 暂停不会被自动续歌恢复。结束陪听只删除她的待播，当前已播放的歌曲继续。

## 连接、权限与恢复

桥接接口为 `POST /api/companion/join`、`heartbeat`、`leave`，仅接受后台配置的 Bearer 连接密钥，另有限流和输入校验，不使用普通网页会话。所有接口返回稳定的 `COMPANION_*` 错误码，不返回歌曲上下文、房间密码或用户聊天。AiChat 仅识别已配置站点的链接，实际请求目标固定为配置地址，不访问消息内任意 URL，也不跟随重定向。

AiChat 每 15 秒续期一次，Redis 键 `openmusic:companion:v1:<roomId>` 保存 75 秒租约；音乐服务每 5 秒清理过期成员。bot 为不可控播的独立成员，不会成为房主、管理员或临时主控；听歌记录可显示她为陪听对象，不累计 bot 用户听歌时长。踢出后心跳不会让她重新进入。

AiChat 在新表 `music_companion_sessions` 中保存会话身份，凭证复用现有配置加密；普通网络中断在租约期内继续连接。音乐服务重启后，AiChat 会在有效租约内尝试恢复同一身份，仍受房间访问、封禁与真人在线条件约束。租约过期或真人全部离开后，需要重新邀请。服务端重启不恢复无人陪听的待播占位歌曲。

## 发布与回退

独立自动化验证无需关闭当前网站。当前朋友版 Docker 镜像复制服务端源码和 `client/dist`，因此代码更新需要先在项目根运行 `npm run build:check`，再重新构建并启动朋友版音乐容器；仅执行 `start-music.ps1` 的 `--no-build` 不会加载新代码。使用该部署时可运行 `docker compose -f docker-compose.friends.yml up -d --build`。这会短暂重启音乐容器，Redis 数据卷沿用。微信 bot 需要重启整个后台进程，工作台的停止/启动按钮只控制监听，不加载新 Python 源码。最后刷新两个网页。

观察 `[companion] join ok`、`refill ok`、`refill unavailable`、`refill upstream error` 与工作台状态；这些日志不是完整监控。若要回退，先关闭音乐后台的陪听开关及 AiChat 的陪听开关，等待清理，再回退两端代码。新增运行配置默认关闭；租约自动过期，新 SQLite 表保留即可，无需删除既有配置或 Redis 数据。
